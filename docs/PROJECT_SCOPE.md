# 项目边界与 v1.0.0 冻结决定

> 决定日期：2026-10-21。仓库所有者授权维护者直接拍板。本文件是之后所有改动的准绳：不在第 6 节"什么情况才开新版本"里的事，默认不做。

## 1. 这个项目是什么

一个基于**固定公开语料**的中国法律条文检索与问答工程项目。它要证明的不是"效果有多好"，而是四件事：

1. **数据可复现**：语料是一个公开数据集的固定版本，236 个文件逐个 SHA-256 校验，任何人都能下载到完全相同的文本。
2. **检索可解释**：自研中文 BM25、法律名与条号精确查表、可选向量检索，每个结果都有 ranking trace。
3. **评测可审计**：每个数字都写明用了哪份语料、哪套题、有什么局限，负结果照样保留。
4. **生成有边界**：证据不足或请求越界时，系统可预测地停止，而不是编一个答案。

## 2. 决定一览

| 编号 | 决定 | 理由 |
| --- | --- | --- |
| D1 | 发布 `v1.0.0` 作为**范围冻结版本**；之后只修正确性 bug，不加功能 | 项目已经覆盖数据、检索、评测、服务、中断恢复、批任务六层，继续加层只会稀释主线 |
| D2 | **唯一语料**：Hugging Face `Kuugo/Chinese_Law` revision `a829f47d` 的 236 个文件，逐字节一致，见 [语料清单](../configs/corpus/kuugo_chinese_law_a829f47d.manifest.json) | 旧的本地快照里 17 个文件被改过、12 个文件不在该数据集中，来源都没有记录、无法核验。核对发现其中的刑法是 2011 年修正前的旧文本（盗窃罪还写着死刑），公司法是 2023 年修订前的旧版。无法核验来源的文本不能进入冻结版本 |
| D3 | **评测**：开发集 `legal-eval-dev-v1`（113 条）加合成条号集 `citation_lookup_v2`（708 条）；不建留出集，所有数字都按开发集数字报告 | v3 的题目全部由大模型生成，并且被反复用来做开发决策。没有人工撰写、冻结后才使用的留出集，就不声称泛化能力 |
| D4 | **检索重构止于 R2**；R3（BM25F 重写）、R4（服务层索引缓存）、R5（混合检索与重排调优）取消 | R3、R4 是性能和架构改进，不改变正确性；R5 需要 GPU 或付费 API，而且没有留出集就无法证明收益 |
| D5 | **M7 不做界面**，只做文档收尾：本文件、README、[项目复盘](../reports/CASE_STUDY.md) | 调试界面不改变任何结论；复现说明和复盘才是复用与面试需要的 |
| D6 | 草稿 PR #31 **关闭，不合并**；分支保留作历史 | 165 个文件、约 2.5 万行，主体是 SmartCN 和 Elasticsearch IK 分词对照（负结果）加新的治理层；它自己的提交也写着"默认取舍未解决"，并且与 R2 改的是同一批函数 |
| D7 | **流程简化**：分支 -> PR -> CI 全绿 -> 合并；只有用户可见的变化才打 Tag | M0-M6 的 STATE、回执、交接文档已经比代码本身还重。它们作为历史保留，不再继续维护 |
| D8 | **模型调用一律走 SiliconFlow，本机不跑本地模型**（v1.0.0 发布后由所有者追加）。向量检索默认用 `BAAI/bge-m3`，重排用 `BAAI/bge-reranker-v2-m3`，两者在 SiliconFlow 上免费；生成默认用 `deepseek-ai/DeepSeek-V4.1-Flash`（收费，在 SiliconFlow 列出的 DeepSeek 型号里最便宜）；LLM judge 仍用 `deepseek-ai/DeepSeek-V3`，不让模型给自己的回答打分。本地模型的代码保留，只有显式指定才会加载。允许在冻结语料上把向量检索、RRF 和重排各测一次，只报告、不调参，默认检索器仍是 BM25 | 本机内存 16 GB，本地 embedding 模型或 Ollama 和其他程序一起跑会把内存占满；这几个开源模型 SiliconFlow 都有托管。补测向量检索是 v1.0.0 最大的空缺：生活化描述的 Hit@5 只有 0.444，需要知道向量检索在同一份语料上能补上多少 |

## 3. 冻结版本包含什么

| 层 | 内容 | 状态 |
| --- | --- | --- |
| 数据 | 固定语料清单、`fetch-corpus` 下载、`verify-corpus` 逐字节校验；解析器支持两种行格式和"第X条之Y" | 冻结语料：236 部法律、19276 条，引用碎片 0，同号冲突 3 组（源文件畸形行） |
| 检索 | 自研 BM25（默认）、dense、RRF、可选 reranker；法律别名精确匹配与条号查表 | 默认 `bm25`、不开 reranker；dense 和 reranker 走 SiliconFlow（D8） |
| 评测 | `retrieval-audit` 深度审计、语料完整性审计、合成条号集生成、bootstrap 置信区间 | 基线见 [v1.0.0 基线报告](../reports/retrieval/V1_0_BASELINE.md) |
| 问答 | 高风险请求预拒答、证据充分性检查、引用编号检查、资料不足时的停止模板 | 生成走 SiliconFlow，需要 API Key，默认不调用 |
| 服务（v0.5.0 至 v0.7.1 已发布） | FastAPI、PostgreSQL/pgvector 版本化快照、LangGraph checkpoint 与预算、Celery 批任务、可选脱敏观测 | 保持原样，不再扩展 |

## 4. 明确不做

- 不再补录、抓取或手工修改法律文本。需要更多法律时，换用一个新的公开版本并生成新的语料清单，作为新版本发布。
- 不再新增数据库、队列、框架、Agent 或界面。
- 不在本机运行本地模型（D8）。不重跑历史上的多模型生成和 LLM judge 实验；向量检索和重排只按 D8 在冻结语料上各测一次。历史数字保留为历史，并标明条件。
- 不在开发集上继续调参或挑选配置。
- 不合并 PR #31 的任何部分。

## 5. 冻结时接受的已知局限

这些问题都已确认、已写明，冻结版本不再修：

- **语料覆盖**：236 个文件全部是全国人大及其常委会通过的法律，截止 2025-01-01；不含宪法、国务院行政法规（如工伤保险条例）和司法解释，之后的修订也不在内。
- **许可证**：数据集最初的版本在 README 中声明 `license: mit`，2025-04-24 的两次 README 改写删掉了这行，当前版本没有许可证声明。仓库只保存语料清单，不分发法律文本。
- **评测集**：开发集由大模型生成，未经法律专业审核，被反复用于开发；没有留出集。合成条号集的问题直接使用语料标题，精确查表必然命中，它只证明解析路径通了。
- **向量检索未重跑**：dense、RRF 的历史数字来自旧语料和修复前的解析器。在冻结语料上重跑需要重建 embedding cache（本机 CPU 估计 2 小时以上），Qwen3 还需要付费 API，所以没有重跑。
- **API 模型无法固定版本**：SiliconFlow 不提供模型版本号，同名模型以后可能被替换，所以向量缓存只能记录提供方和模型名，不能像语料那样逐字节核验。服务层的向量检索仍只接受能核验版本的本地模型，因此服务层只用 BM25。
- **服务路径**：每个请求都重新构建一次 BM25（本机约 1 秒），而且使用默认参数而不读配置。冻结语料不含废止法律，所以降权参数的差异不影响结果。
- **条号解析**：不支持俗称（如"民诉法解释"）、条号范围展开和"本法"指代；简称可能出现在普通词语里被误识别（"有限责任公司法定代表人"会识别出"公司法"）。
- **置顶只在 BM25 内生效**：RRF 融合和 reranker 可能把精确命中排下去。默认配置不开这两项。
- **查询分析与证据检查**：`query.py` 的常用法律名单和证据检查中的法律名覆盖仍是子串判断，只用于路由、风险标记和证据提示。

## 6. 什么情况才开新版本

| 触发条件 | 版本 | 要求 |
| --- | --- | --- |
| 修复会给出错误法律依据的正确性 bug | `v1.0.x` | 回归测试先行；基线数字变化要写进 CHANGELOG |
| 数据集发布新 revision，或换用另一个公开语料 | `v1.x.0` | 新语料清单，重跑基线；不覆盖 v1.0.0 的数字 |
| 有了人工撰写、冻结后才使用的留出集 | `v1.x.0` | 此时才值得重新讨论混合检索、重排之类的效果优化 |

除此之外的想法记在 issue 里，不进代码。

## 7. 本地环境整理（需要所有者自己执行）

1. 把旧语料目录 `Chinese-Laws/Chinese-Laws` 改名为 `Chinese-Laws/legacy-local-snapshot`，不再使用。
2. 下载冻结语料并校验，校验必须通过：

   ```powershell
   python -m legal_rag.cli fetch-corpus --output-dir Chinese-Laws/Chinese-Laws
   python -m legal_rag.cli verify-corpus --data-dir Chinese-Laws/Chinese-Laws
   ```

   国内网络可加 `--endpoint https://hf-mirror.com`。
3. 主 checkout 从 `codex/chinese-bm25-optimization` 切回 `master`。venv 以 editable 方式安装主 checkout，不切回的话，命令行运行的是 PR #31 的代码。
4. 旧的 `artifacts/indexes`、embedding cache 和 PostgreSQL 快照都基于旧语料，需要用冻结语料重建后才能和 v1.0.0 的代码与数字对应。
