# 项目 Agent 执行规则

本文件是用户项目要求的补充，不覆盖系统规则、用户最新指令或已有更高优先级仓库指令。仅阅读它不会触发远程写操作，需用户发送开始/继续执行指令。

## 进入项目

先确认工作目录、origin、默认分支、HEAD 和 dirty 状态，再读取 STATE/HANDOFF、主方案当前里程碑、对应代码/测试/历史文档。不能假定主分支叫 main，也不能把用户的新提交退回到文档基线 SHA。

仓库事实优先于旧聊天总结：已完成能力先复用，已修复缺陷保留回归测试，不重复造一套实现。

## 默认执行单位

一次一个里程碑；用户明确要求多个阶段才连续执行，但每个阶段仍有独立门禁与发布。禁止一次性实现全部 M0—M7，禁止把多 Agent、更多数据库和大规模 UI 当顺便任务。

当前权限范围由用户启动指令决定。正常开发/测试/分支 push/PR/合并/发布若已经授权，不逐条重复请求确认；超出额度、权限、数据公开或生产变更范围时，只停止相关动作并说明。

## 开发顺序

1. 在合适工作分支复现或编写会失败的测试，明确本阶段应有行为。
2. 最小实现，保留 CLI 与已有评测、数据、历史结果。
3. 执行适用的离线、集成和故障检查，记录真实结果。
4. 审查改动和秘密，明确路径 stage，完成一个可测试子任务就 commit/push 分支。
5. 更新 README、CHANGELOG、验收报告、版本源、HANDOFF 与 PR。
6. 最终候选 CI 通过后按规则合并；核实合并提交，Tag 指向该提交。
7. 发布并验证 Release；补发布回执、STATE/HANDOFF，向用户报告后停止。

## 禁止行为

不 force push，不移动已发布 Tag，不删除别人的分支，不擅自 stash/reset/覆盖未提交修改，不绕过 review，不把 API key/私人对话/完整语料/模型缓存推到公开仓库。

不虚报测试、CI、Tag、Release、性能或完成率。没有命令实际执行就写 not_run；skipped 不是 passed。真实模型未评估就不声称质量提高。

不能靠在 Prompt 里写“最多两轮”代替程序预算；不能把引用存在解释成语义支持；不能把 checkpoint 解释成所有外部请求 exactly once；不能把 Redis 当唯一会话持久层。

## 费用与网络

默认禁用 live model。已授权 live 调用也必须带明确最大次数/预算，先少量样例，重试计入额度。无网络/缺凭证时完成可独立做的离线工作，记录受阻部分，不用假数据当实测。

## 工具与 GitHub

优先使用工作区 git/gh 或已连接 GitHub 工具。工具不可用时报告具体哪个动作失败，不谎称所有 GitHub 能力不可用。发布动作失败后不得从头重复所有动作，先检查远程已完成的步骤。

push 工作分支、合并 master、Tag、Release 是不同状态。发布的最终成功以远程读取验证为准，不只依据本地进程退出码。

## 交接

每次结束前更新 HANDOFF，包括已修改文件、真实测试、当前 branch/HEAD、是否 commit/push、PR/Tag/Release 状态、阻塞与下一条可执行动作。

无法完成整个阶段时保存部分成果，不进入下一阶段掩盖问题。需要补回执时先核验 Release，不能重复发版。详见 MASTER_PLAN 第 13 和 16 节。
