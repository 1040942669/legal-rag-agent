## 实际改动

| 文件/模块 | 改动原因 | 对外行为变化 | 兼容性 |
|---|---|---|---|
| `legal_rag/models.py` | 建立可验证回答与验证结果 schema | 显式区分四种回答模式、claim/source、快照/权限范围和分层检查状态 | 保留旧纯文本转换入口，标记为 legacy adapter |
| `legal_rag/verifier.py` | 拆开结构、行为、范围与未知语义 | 免责声明或法律正文中的“不得/不能”不再冒充拒答；伪造、未对齐，以及配置范围检查时的越权引用失败关闭 | 原 `passed` 仅表示配置要求的结构/行为检查通过，不代表法律正确 |
| `legal_rag/chat.py` | 防止无效草稿和越界证据被交付 | 显式注入可信 `VerificationContext` 时先按范围过滤；失败草稿进入有界终态且最终响应再次验证 | 当前 CLI 不提供认证身份、租户隔离或默认快照；Trace 另存生成尝试与最终交付 |
| `legal_rag/evaluation.py`、`legal_rag/judge.py`、`legal_rag/tracing.py`、`legal_rag/json_utils.py` | 修正指标分母、失败归因和不可信输出边界 | retrieval-only 使用 `null + reason`；Judge 三态分开；拒答召回、过度拒答和澄清分母独立；模型 JSON 严格解析；被拒绝草稿内容型诊断只留计数 | 旧 CSV 的 `-1` 仅作兼容哨兵，不进入新均值；Trace 不是全链路脱敏系统 |
| `docs/METRICS.md`、`eval_cases/legal_eval_cases_v2.jsonl` | 固化新口径和期望行为 | 报告记录 schema 版本、明确分母与 canonical metric 映射 | 历史报告不覆写，不把新旧总值直接比较 |
| `tests/test_m1_*.py`、`tests/fixtures/m1_verification_examples.json` | 覆盖 M1-T01 至 M1-T10 和两组改前/改后边界 | fixture 明确为虚构、非法律文本，只证明规则边界 | 不读取完整语料，不调用模型 |
| `scripts/quality_gate.py`、`.github/workflows/quality-gate.yml` | 建立累计、机器可读的 M1 门禁 | M1 累积 M0 的 7 项与 M1 的 10 项；skip/xfail/零测试/JUnit 异常失败关闭；CI 上传 JSON | M0 入口仍保留；未知 milestone/mode 返回配置错误 |
| `legal_rag/env.py`、`legal_rag/llm.py`、`legal_rag/embeddings.py` | 防止本地离线门禁重新载入被忽略 `.env` 或误触 provider | 离线子进程禁用 dotenv，并在 Ollama、SiliconFlow、SentenceTransformer、远程 embedding 边界拒绝真实调用 | 普通运行未设置开关时保持原行为；显式 false 时失败关闭 |
| `pyproject.toml`、`uv.lock`、README、CHANGELOG | 冻结 `0.2.0` 候选和公开边界 | 包版本、门禁命令、真实测试数量和限制保持一致 | lock 只改变本项目版本，不升级依赖 |
