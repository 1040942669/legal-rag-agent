## 机制与可证明边界

1. API 只接受认证 principal 可访问的服务端注册 opaque ref。一次 PostgreSQL 事务写 job 与 outbox；`202` 表示已接受，不表示 Redis 已收到。GET/cancel 以 user、scope、profile 共同约束 owner，foreign/missing job 同样为 404。
2. dispatcher 领取带租约的 outbox；Celery 消息只含 job ID 与 schema version。Redis 只做 broker，不持久保存会话/结果。worker 晚确认、worker-loss 拒收、有限重试，数据库 lease epoch、item 唯一键与 immutable artifact 对账重复投递。无法承诺任意 side effect exactly-once。
3. 评测复用 M2 provider-free offline lifecycle，按 case 保存进度。导入复用 M3 prepared import：验证预构建 artifact、原子导入、可选 HNSW、read-back validate，最后 activation。六个阶段是工作边界，不虚构每个 chunk 的即时 embedding 进度。索引失败时 active snapshot 不移动。
4. 本地 JSONL 观测为 opt-in；远端 Langfuse exporter 默认关闭，需要明确 data-flow ack。导出 payload 白名单排除全文、凭证、token 与个人信息；失败不能阻塞主链路。

决策与回滚条件见 [ADR-004](../../docs/refactor/decisions/ADR-004-m6-batch-jobs-observability.md)。
