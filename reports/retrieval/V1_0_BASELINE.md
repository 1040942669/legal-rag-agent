## 3. 和旧本地语料比：同样 101 道题

旧本地语料是 R0-R2 报告使用的快照。检索代码相同（R2；"第X条之Y"的解析只影响冻结语料里的刑法），只换语料：

| 指标 | 旧本地语料 | 冻结语料 |
| --- | ---: | ---: |
| 法律 / 条文数 | 205 / 18356 | 236 / 19276 |
| Hit@1 | 0.554 | 0.614 |
| Hit@5 | 0.703 | 0.723 |
| Hit@20 | 0.802 | 0.802 |
| MRR@10 | 0.622 | 0.663 |

17 道题的首个命中名次变了，15 道变好、2 道变差。这些变化来自**语料本身**，不是算法改进：冻结语料多了 31 部法律，各个词的 IDF 统计随之改变；另外劳动合同法、劳动争议调解仲裁法、海商法、票据法这 4 部法律的 540 个条文带有编者加的条旨（如"【不订立书面劳动合同的法律责任】"），给词面检索多提供了关键词。所有差异都落在置信区间内，所以**不应报告为效果提升**。

## 4. 为什么停用旧本地语料

逐文件和 Hugging Face 原版比对（git blob 哈希）的结果：

| 类别 | 文件数 | 说明 |
| --- | ---: | --- |
| 与原版逐字节一致 | 176 | 修改时间都是 2025-06-18，即原始下载日 |
| 原版有、但内容被本地改过 | 17 | 包括刑法、劳动合同法、劳动法、公司法、专利法、个人信息保护法等 |
| 原版没有 | 12 | 宪法、工伤保险条例、物业管理条例、已废止的合同法/民法通则/继承法、两个司法解释等 |
| 原版有、本地缺失 | 43 | 按文件名排序后连续的一段，看起来是当初下载不完整 |

按所有者回忆，被改动和新增的文件主要是让 AI 从网上找来的。抽查发现：

- **刑法是旧文本**：第二百六十四条（盗窃罪）还是 2011 年刑法修正案（八）之前的写法，含"处无期徒刑或者死刑"，没有"入户盗窃、携带凶器盗窃、扒窃"；整部文件 183 KB，原版 232 KB，53 个"第X条之Y"条文（如危险驾驶罪，第一百三十三条之一）一个都没有。
- **公司法是旧版**：第三条还是"股东以其认缴的出资额为限对公司承担责任"，即 2023 年修订前的写法。
- **网页残留**：刑事诉讼法末尾混入了"编 辑： … << 返回首页 / 相关文章"。

一个法律问答系统如果用这样的文本回答"偷东西会不会判死刑"，会给出错误的依据。所以冻结版本只使用能逐字节核验的公开版本，宁可少几部法律。

## 5. 局限

- 只有 BM25。dense 和 RRF 需要在冻结语料上重建 embedding cache（本机 CPU 估计 2 小时以上），Qwen3 需要付费 API，均未重跑；历史数字见 [历史实验结果](../RESULTS_SUMMARY.md)，条件不同，不能和本报告直接比较。
- 开发集由大模型生成、被反复使用、未经法律专业审核。
- 延迟取决于机器负载，跨运行可差 10% 以上，只适合同一次运行内比较。

## 复现命令

```powershell
python -m legal_rag.cli fetch-corpus --output-dir <语料目录>
python -m legal_rag.cli verify-corpus --data-dir <语料目录>
python -m legal_rag.cli profile-data --data-dir <语料目录> --profile-dir <out>/profile --report-dir <out>/profile
python -m legal_rag.cli build-index --data-dir <语料目录> --profile-path <out>/profile/data_profile.json --index-root <out>/indexes --chunk-strategy article
python -m legal_rag.cli retrieval-audit --index-dir <out>/indexes/article --retriever bm25 `
  --cases eval_cases/legal_eval_dev_v1.jsonl --cases eval_cases/citation_lookup_v2.jsonl `
  --depth 20 --data-dir <语料目录> `
  --corpus-manifest configs/corpus/kuugo_chinese_law_a829f47d.manifest.json `
  --output-dir <out> --prefix v1_bm25
# 重新生成合成条号集（结果应与入库文件逐字节一致）
python -m legal_rag.cli generate-citation-cases --data-dir <语料目录> --output eval_cases/citation_lookup_v2.jsonl
```
